# Change, preview, apply and restore

## Establish a recoverable target

Capture current theme/configuration identity, original affected values and
publication/default/user-selection state. Retain recovery evidence privately,
not an instance-wide export. Resolve styles through actual relationships and
reverse links; names alone do not prove that a style is private to a draft.

For a scoped trial, prefer a supported custom unpublished draft or another
qualified isolated target. Verify that duplication really produced an
unpublished target. Fixed vendor themes are not ordinary custom themes to edit.

Existing published-theme edits can become live on refresh. Draft creation and
editing may also autosave. Wizard navigation or an accessibility value does not
prove persistence; reconcile the actual saved identity before repeating authoring.
Continue a retained interrupted target rather than creating replacements.

## Author through the supported mechanism

Inspect the actual release's create/manage/editor controls. Use the host's
browser/app guidance and an owned background/headless context where suitable.
Re-inspect after interruptions; leave unrelated windows and records alone.

For MCP administration, discover the exact tool schema. Use
`servicenow-operations` for version/value guards, operation IDs, read-back and
uncertain outcomes. A tool limited to one login property is not an arbitrary
property/script writer or a theme lifecycle API. Unsupported changes require a
concrete capability decision, not a hidden endpoint or business-record workaround.

Record only intended settings and inspect saved values after editing. Verify
related changes together on the target experience rather than presenting
unrelated writes as one coherent theme.

### Guarded style changes

When exposed, discover `local_admin_patch_theme_style_pair` and its restore
schema. Respect the current tool's theme ownership, publication and style-sharing
guards. Supply actual identities, current versions, full raw hashes and required
original values in the schema's formats.

Retain the returned complete-originals snapshot. Do not truncate, reserialize
or reconstruct generated style JSON for restoration. Preserve unrelated raw
content. A change to one component token does not change every component or
an entire named style preset.

Paired writes may be non-atomic. Preserve each stage and the snapshot from an
error, reconcile both styles read-only, and report partial/uncertain state.
Do not resend the patch. For authorized restoration, use the snapshot and
latest versions/hashes; reject unrelated drift rather than overwrite it.
Check exact source restoration separately from visible appearance.

## Preview and application reach

Use the actual experience preview, then inspect the intended experience/user.
Preview can contain live data; theme inspection does not authorize editing it.
Verify saved settings and affected rendering, including interaction states,
typography, shape and asset fit, rather than only an editor thumbnail.

Generated palettes and token aliases can produce rendered colors different
from an input RGB value. Inspect actual bindings and affected computed styles;
do not claim a whole-page color change from a changed source token alone.

Publication makes a theme available. Default ordering does not guarantee
migration of personal preferences. Change only the requested publication,
default or personal-selection scope and verify after refresh. Portal, login
and workspace-specific branding require their own targeted checks.

## Guarded publication and default lifecycle

Where exposed, `local_admin_theme_lifecycle_assess` captures the selected theme,
styles, mappings and preferences with a bounded assessment lifetime/state hash.
Use its current contract and fresh assessment; inventory alone is not approval.
Source contract pins, ownership, completeness and exclusivity guards remain in
force even if the request uses ordinary product language.

Publication and default application are separate operations. Use each tool's
assessment/snapshot, current state hash, new operation ID and required
confirmation fields. Retain returned mapping identities. A source-confirmed
default does not prove the named user's actual selection or inheritance.

For an authorized user-selection trial, wait for the required source stage to
complete. Use the supported Preferences > Theme selector, inspect the actual
experience, then restore the recorded theme and variant. Selecting an account
for observation does not authorize changing its preferences. Read visible
selected state rather than forcing hidden controls or deleting preference rows.

Reconcile the same lifecycle snapshot before restoration. Use fresh returned
state, not an earlier application hash. Native UI can replace preference rows
or advance audit metadata while restoring meaningful settings: verify exact
user/keys/values, old-ID absence and actual replacement identities using the
tool's required evidence. Preserve unrelated settings and report identities
honestly. Do not recreate old rows or rewrite history to fake byte-identical
restoration. Pending native stages and unrelated drift still block progress.

Restore original mapping order before removing a cycle-created publication
mapping, following the tool's supported sequence. Keep original mappings,
drafts, assets and operation history. Finish a dependent lifecycle before
restoring its styles/assets if those operations share guards.

An asynchronous acknowledgment is not completion. Follow the tool's read-only
reconciliation contract until the stage is confirmed or remains explicitly
uncertain. Preserve consumed operation IDs; do not replace the cycle, replay
the write or attempt speculative rollback. Hold conflicting changes, not
unrelated ordinary work.

## Restoration and incomplete outcomes

Restore original meaningful settings, selection and default within the
authorized scope, then verify both source state and actual appearance.
Unpublishing, deleting a draft and deleting assets are separate effects; retain
them unless those actions are included and their required gates are satisfied.

Re-read before guarded restoration and use the actual current version/value
plus a new operation ID. A deliberate restoration after reconciled state is
not a resend after response loss. Audit versions/timestamps normally advance;
animated rendering need not be pixel-identical.

A genuine validation error may support a minimal input correction after
reconciliation. Source/configuration denial stops that path. Preserve original
state and incomplete effects, and report blocked restoration plainly rather
than declaring success from source writes alone.
